# MIXLAB — сайт о сведении музыки

Автор: Калиниченко Владислав Дмитриевич. Учебный проект по веб-программированию.

## Открыть проект в Visual Studio Code

1. Распакуйте ZIP целиком в новую папку.
2. В VS Code выберите «Файл → Открыть папку» и укажите папку, содержащую `index.html`.
3. Для статической версии запустите Live Server либо `python -m http.server 8000` из терминала этой папки.
4. Откройте `http://localhost:8000`. Открытие файлов двойным щелчком (`file://`) не подходит для загрузки JSON и серверных функций.

Пять музыкальных инструментов, поиск и проверочный список работают в браузере. Для общих обсуждений, новостей и статистики нужен PHP-сервер.

## Основной сайт

https://vlad-mixlab.alwaysdata.net/ — основная версия с PHP/XSL и общей БД.

Новости, гостевая книга, темы и ответы форума, голоса и статистика просмотров сохраняются на сервере. Рейтинг показывает среднее всех голосов и позволяет менять свой голос. Счётчик показывает просмотры и уникальных посетителей, включая итоги за текущий день по московскому времени.

GitHub Pages остаётся дополнительной статической копией: браузерные обсуждения и счётчик там не объединяются. Для проверки работ используется адрес alwaysdata.

## Запуск настоящей БД локально

Нужен PHP 8.1+ с PDO и расширением `pdo_sqlite` (SQLite) или `pdo_mysql` (MySQL). Рекомендуется поддерживаемая версия PHP 8.3+; устаревший PHP 4 из методички не используется.

Из терминала в корне проекта:

```sh
php server/setup.php
php -S 127.0.0.1:8000 server/router.php
```

Первая команда попросит придумать пароль администратора длиной от 10 символов. Ввод в обычном терминале может быть видимым. Пароль хранится только как хеш. После запуска откройте `http://127.0.0.1:8000/admin/news.html`, войдите и опубликуйте новость. Затем откройте ленту в другом браузере: запись будет общей.

SQLite-файл и конфигурация создаются **в папке `mixlab-private` рядом с папкой проекта**, вне публичного каталога. Сохраняйте эту папку при переносе сервера: ZIP исходников не содержит вашей рабочей БД и пароля. Первое подключение создаёт таблицы и переносит опубликованные записи из JSON. Повторный запуск их не дублирует.

Для MySQL импортируйте `database/schema.mysql.sql`, затем задайте серверные переменные окружения `MIXLAB_DB_DSN` (например, `mysql:host=127.0.0.1;dbname=mixlab;charset=utf8mb4`), `MIXLAB_DB_USER`, `MIXLAB_DB_PASSWORD`. Можно также прописать ключи `dsn`, `user`, `password` в приватном `mixlab-private/config.php`. Хеш администратора задаётся командой настройки или переменной `MIXLAB_ADMIN_PASSWORD_HASH`.

В API используются подготовленные SQL-запросы, проверка длины полей, серверная сессия и защита от межсайтовой отправки формы. Пароли и действующие БД не добавляются в GitHub.

## Погода и курсы

`tools/refresh_informers.py` получает погоду Open-Meteo для семи российских городов и курсы Банка России. Информеры загружают `data/weather.json` и `data/currency.json` с того же сайта, без обращений браузера к зарубежному погодному API и без сторонних скриптов.

Workflow `.github/workflows/informers.yml` обновляет данные раз в три часа, при изменении `main` и при ручном запуске. GitHub может задерживать расписание и отключать его после длительной неактивности публичного репозитория. Погода старше 8 часов помечается устаревшей; для курсов отслеживается время последней проверки (36 часов), а дата действия курса показывается отдельно. Ошибка источника сохраняет последнюю успешную копию, а не подменяет её выдуманными значениями.

Для локального обновления:

```sh
python tools/refresh_informers.py
```

Доступность самого GitHub Pages зависит от сети посетителя. Проверка из российской сети отдельно не проводилась.

## Страницы и сервисы

- `index.html`: введение, погода, курсы, последние новости.
- `materials.html`: статьи, словарь, полезные ссылки, список проверки.
- `services/`: пять музыкальных инструментов, гостевая книга, форум, поиск, общая лента.
- `admin/`: управление новостями; ссылки на статистику и рейтинг.
- `xml.html`: работающий каталог XML/XSL; `database.html` и `rss.html`: пока пустые разделы.

На основном PHP-сайте статистика, рейтинг, форум и гостевая книга используют общую серверную БД. На странице `admin/community.html` администратор может скрывать/восстанавливать сообщения, окончательно удалять скрытые записи (тему вместе со всеми ответами), удалять отдельные анонимные оценки с пересчётом рейтинга, ограничивать публикации с конкретных подключений и управлять запрещёнными выражениями. Отдельного пароля для форума не нужно: используется вход администратора новостей. IP-адреса и идентификаторы браузеров хранятся только в виде HMAC, в публичных ответах не выдаются. Голос определяется устойчивым cookie браузера, а не гарантированной личностью человека.

## Проверки и обслуживание

```sh
python tools/build_search.py
python tools/check_site.py
```

После изменения текстов запустите `build_search.py`: индекс включает весь текст основного содержимого, а не только ключевые слова. После добавления страницы также обновите `data/pages.json` и `sitemap.xml`. Проверка охватывает локальные ссылки, якоря, идентификаторы, язык страниц, общий поиск и JSON. Отдельные функции проверены сценариями `tests/` (если указан соответствующий тестовый файл).

Метатег подтверждения Google сохранён. Наличие метатега и карты сайта само по себе не подтверждает индексацию: фактический статус нужно смотреть в кабинете поисковой системы. Проверка внешним W3C-валидатором и регистрация в поиске требуют отдельного подтверждения; они не объявляются выполненными автоматически.

Подробная связь с требованиями: `LABS.md`. Публикация: `DEPLOY.md`.

## Каталог XML

В разделе «XML» доступны 18 заметок по сведению в таблице с поиском во всех семи колонках, отбором по теме/уровню и сортировкой по любой колонке. На странице есть ссылки на исходные XML, XSL и XSD. Данные находятся в `data/mixing-news.xml`, схема — `data/mixing-news.xsd`, оформление и серверный отбор — `data/mixing-news.xsl`. Запуск PHP и демонстрация требований второй работы описаны в [LAB2.md](LAB2.md).

Кнопка обновления на alwaysdata вызывает `api/weather.php`: выбранный город проверяется у Open-Meteo, показываются время прогноза и время успешной проверки источника с точностью до секунды. Прежние значения не подменяются текущим временем; одинаковый прогноз, недавняя проверка и сбой источника имеют отдельные сообщения. Результат хранится в закрытом общем кэше, запрос к источнику ограничен одним в минуту для города.

Исходные XML/XSL/XSD сохранены в UTF-8 с меткой BOM для распознавания обычными редакторами. В `data/.htaccess` задаются XML MIME-типы, `charset=UTF-8` и перепроверка кэша. Объявления `encoding="UTF-8"` сохранены; содержание записей не изменено.

Окончательное удаление сообщений и оценок требует входа администратора и CSRF-токена. Публичное сообщение сначала нужно скрыть; удаление темы и её ответов выполняется в одной транзакции. Удалённые записи исчезают из публичного раздела и списка управления. Интерфейс запрашивает подтверждение необратимого удаления. Карточка «Рейтинг» в разделе управления открывает публичную страницу для голосования. Список отдельных голосов и их удаление доступны в нижней карточке «Управление сообщениями и рейтингом».
