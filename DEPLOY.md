## GitHub Pages

Workflow «Обновить информеры и сайт» публикует только HTML, CSS, JavaScript и публичные данные; PHP и конфигурация БД в опубликованный артефакт не входят.

Для нового окружения: Settings → Pages → Build and deployment → Source → GitHub Actions. Должны быть разрешены Actions и публикация в окружение `github-pages` из ветки `main`. Если workflow запрещён настройками аккаунта, включите его вручную в Actions. Ключи погодного сервиса и валютного API не нужны.

Файлы данных обновляются коммитом бота. При конфликте с одновременным изменением `main` workflow завершится ошибкой, не перезаписывая изменения; повторите запуск. Страница Actions показывает конкретную ошибку.

## PHP-хостинг

1. Выберите сервер с PHP 8.1+ и PDO SQLite/MySQL.
2. Разместите файлы сайта в публичном каталоге.
3. Приватную БД, хеш пароля и реквизиты храните вне публичного каталога (`mixlab-private` рядом с папкой сайта по умолчанию).
4. Для Apache запреты в `.htaccess` закрывают `server`, `database`, `tools` и файлы БД; убедитесь, что `AllowOverride` разрешён. Для Nginx настройте эквивалентные запреты. Не публикуйте служебные каталоги как скачиваемые файлы.
5. Выполните настройку, описанную в README. Проверьте публикацию новости и просмотр в другом браузере.
6. Используйте HTTPS. Встроенный `php -S` предназначен для локальной разработки, а не публичного размещения.

После переноса весь сайт должен обслуживаться одним PHP-хостингом. Автоматическое подключение произвольной внешней БД напрямую из JavaScript не используется.


## Подготовка переноса и индексация

Для переноса требуется аккаунт хостинга с PHP 8.1+, DOM, XSL, PDO SQLite или MySQL, HTTPS и поддержкой `.htaccess`. Поддержка XSL есть в документации alwaysdata; тариф Free предназначен для некоммерческих сайтов. Регистрация может требовать проверку карты. Новый аккаунт/публичный адрес пока не созданы.

После получения реального адреса сайта можно подготовить каталог загрузки:

```bash
python tools/package_php.py --base-url https://YOUR-SITE.example/ --output /path/to/new/upload-folder
```

Команда копирует PHP и публичные файлы, меняет адреса в sitemap/robots, исключает Git и служебные тесты. Она не загружает файлы, не создаёт аккаунт и не подставляет секреты. Затем нужно настроить БД и пароль администратора по README, проверить `xml.html` без JavaScript и публикацию новостей. Погодные данные на новом хостинге потребуют настройки обновления/синхронизации; GitHub Actions по-прежнему обновляет их в GitHub.

Для оповещения поисковиков подготовлен IndexNow. `indexnow-key.txt` — публичный файл подтверждения сайта, а не пароль учётной записи. Он включён в публикуемую версию. После проверки доступности файла и sitemap:

```bash
python tools/submit_indexnow.py --base-url https://vladislafkalinichenko.github.io/KalinichenkoVD.github.io/
```

При смене адреса сначала опубликовать sitemap/robots для нового сайта, затем вызвать команду с новым `--base-url`. Ответ 200 означает получение адресов, 202 — получение с ожидающей проверкой ключа. Ни один ответ не подтверждает попадание страниц в поисковый индекс. Для проверки Google нужен доступ владельца к Search Console; имеющийся meta-тег подтверждения сохранён. Регистрация ресурса, отправка sitemap и фактическая индексация — разные этапы.


## Основная публичная версия

Сайт с выполняющимся PHP: **https://vlad-mixlab.alwaysdata.net/**.

Раздел `xml.html` обслуживается через `xml.php`: фильтрация и сортировка XML выполняются на сервере через XSL. Публичная HTTP-проверка без JavaScript подтвердила 18 записей и результат из одной записи для фильтра «Стерео + Продвинутый».

Карта сайта и `robots.txt` в этой версии используют адрес alwaysdata. GitHub Pages остаётся дополнительной статической копией. Метатег подтверждения Google добавлен рядом с ранее существовавшим тегом.
